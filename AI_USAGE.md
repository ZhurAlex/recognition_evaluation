## Как использовал ИИ

- ИИ разобрал формат входных данных и предложил план из шагов.
- Код пишу сам. ИИ работает в режиме ассистента: подсказки, объяснения, ревью. Об этом я попросил явно.
- Исключения — фрагменты, которые ИИ написал по моей явной просьбе:
  - ветка bBox в `generate_mask` (правило растеризации, см. решение 12);
  - разбиение `generate_mask` на диспетчер и три метода `_mask_from_*` с docstring (решение 13);
  - `greedy_matching`: алгоритм разобрали вместе, код написал ИИ;
  - механический перенос кода по модулям (решение 16): логика не менялась, вывод сверен с прежним;
  - оркестратор `match_objects` и обновлённый `main`;
  - `build_message` в `report.py` (формат таблицы, решение 19). Структуру `report.py` с разделением на построение текста и вывод в консоль и файл сделал я;
  - исправление ширины колонок в шапке таблицы и `requirements.txt` (`pip freeze`).
- Этот файл ИИ создал как образец по моей просьбе. Дальше я веду его сам, часть записей ИИ добавлял по моей просьбе.

## Что выяснили о данных

- Полигоны хранятся по-разному. В `annotated` у полигона есть вершины в поле `path`. В `ground_truth` вершин нет, форма задана PNG-маской на весь кадр: `road.jpg.images/00001/<nm>.png`, 1000×667, 1 бит.
- Id объектов (`nm`) между папками не совпадают. Например, машина `0.1` в эталоне — это `0.3` в разметке. Сопоставлять объекты нужно по геометрии, а не по `nm`.
- В разметке есть ошибки: пропущен объект (машина `0.4`), есть ложное срабатывание (знак `0.5`), есть лишний id (`0.9`).
- Атрибуты тоже расходятся (`weather`, `oncoming`), но на IoU они не влияют.

Формат первым разобрал ИИ.
Первичная проверка масок и поиск отличий были выполнены еще во время собеседования

## Результат

- 7 пар, 1 пропуск (эталон `0.4`, машина), 1 ложное срабатывание (разметка `0.5`, знак). Во всех парах тип совпадает.
- Итоговая оценка: 8904 / 18063 ≈ **49.3%**.
- Без учёта пропуска и ложного срабатывания вышло бы 49.9%. Оба объекта маленькие, поэтому влияют слабо, а итог определяют крупные барьеры с IoU 0.40 и 0.49. Это и есть взвешивание по площади, которого требует задание.
- Главная ошибка разметки: оба барьера обведены примерно вдвое больше эталона (4609 px против 2377, 7793 против 3568). Именно они тянут итог вниз.
- Полный отчёт: `report.txt`.

## Проверка

- Маски полигонов разметки: форма `(667, 1000)`, тип `bool`, границы маски совпадают с bbox из JSON, значит оси не перепутаны.
- bBox эталона (`0.5`, `0.6`): маска из координат совпадает с PNG-маской до пикселя (783 и 81 пиксель).
- После разбиения `generate_mask` все маски обеих папок не изменились.
- Матрицы: у непересекающихся объектов объединение равно сумме площадей, например 94 + 143 = 237 для эталона `0.4` и разметки `0.5`.
- Матрица пересечений совпала с тем, что было видно в данных при первом разборе: строка эталона `0.4` и столбец разметки `0.5` целиком нулевые.
- Жадный алгоритм дал предсказанный результат: 7 пар, пропуск `0.4`, ложное срабатывание `0.5`. Три слабые разнотипные пары с IoU < 0.01 отброшены.
- Итог 0.4929 совпал с независимым расчётом ИИ.
- После переноса по модулям вывод скрипта совпал с прежним символ в символ.
- эталон, сравнённый сам с собой, даёт 100% на каждом объекте и в итоге, все объекты сопоставились сами с собой. Проверку предложил ИИ, я. Результат проверочного вывода

## Ограничения и что можно улучшить

- из path берётся только первый контур (path[0]). В текущих данных у всех полигонов ровно один контур. Что означают несколько контуров (отдельные части объекта или дырки), в формате не описано.
- Полигоны разметки растеризуются через `ImageDraw.polygon`, который включает граничные пиксели. Скорее всего, у них то же смещение на пиксель, что было у bBox. Проверить нельзя: у эталона нет вершин полигонов. Сильнее всего это влияет на маленькие объекты.
- Сверка жадного алгоритма с венгерским (решение 7) пока не выполнена.
- Имя картинки (`road.jpg`) и номер кадра в пути к маскам (`00001`) заданы в коде. Скрипт обрабатывает одну картинку с одним кадром.
- Данные (`annotated/`, `ground_truth/`) не входят в репозиторий. Без них скрипт не запустится, результат можно посмотреть в `report.txt`.
